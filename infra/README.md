# Netra infrastructure

AWS resources, defined in SAM so a deployment is reproducible from the
repository rather than from someone's console history.

## What this stack contains

The **GitHub webhook receiver** — the minimal production entry point. An HTTPS
endpoint that accepts GitHub deliveries, verifies their signature, and
acknowledges quickly. The investigation workflow is wired behind it in a later
stack; nothing here depends on that work.

| Resource | Purpose |
|---|---|
| `AWS::Serverless::HttpApi` | Public HTTPS endpoint, `POST /github/webhook` |
| `AWS::Serverless::Function` | Verifies the signature and acknowledges (Node 22, arm64, 256 MB, 8 s) |
| `AWS::SecretsManager::Secret` | Webhook secret, **generated by AWS** |
| 2 × `AWS::Logs::LogGroup` | Lambda and API access logs, 14-day retention |
| `AWS::CloudWatch::Alarm` | Fires on a sustained run of handler errors |

## The webhook secret is never written down

The secret is created by CloudFormation with `GenerateSecretString`, so it does
not exist in this repository, in a template, or in a shell history. After
deploying, read it once and paste it into the GitHub App's *Webhook secret*
field:

```bash
aws secretsmanager get-secret-value \
  --secret-id netra/prod/github/webhook \
  --profile netra --region eu-north-1 \
  --query SecretString --output text
```

## Deploying

```bash
pnpm --filter @netra/webhook build      # bundle the handler
cd infra
sam build
sam deploy --stack-name netra-prod \
  --profile netra --region eu-north-1 \
  --capabilities CAPABILITY_IAM \
  --resolve-s3 --no-confirm-changeset \
  --parameter-overrides Stage=prod
```

### If the deploying principal cannot create IAM roles

An AWS **PowerUserAccess** profile cannot call `iam:CreateRole`, so the stack
cannot create the Lambda's execution role. Pass a pre-created role instead:

```bash
sam deploy ... --parameter-overrides \
  Stage=prod ExecutionRoleArn=arn:aws:iam::<account>:role/netra-webhook-role
```

The role needs a Lambda trust policy, `AWSLambdaBasicExecutionRole`, and
`secretsmanager:GetSecretValue` on the webhook secret. See the repository README
for the exact policy documents.

## Cost

Everything here is request-priced and idles at effectively zero: HTTP API and
Lambda are per-invocation, the alarm is $0.10/month, and log retention is capped
at 14 days. The only fixed cost is the Secrets Manager secret, at $0.40/month.
